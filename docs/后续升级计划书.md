## 二、M0 发布收尾（v1.1.1，0.5～1 天）

纯运维/文档类，无大代码改动，优先做掉以消除 v3 的 P0/P2 风险。

- **[P0] 核对并重新部署线上 SCF**：用当前 `scf_bangumi_proxy.js` 覆盖线上函数；配置 `ALLOWED_ORIGINS`（含 `https://localhost`、`http://localhost:5173`）。
- **[P0] 统一签名身份**：确认唯一权威 keystore；用 `git filter-repo`/BFG 清理历史中弱口令 keystore，并视旧密钥为已泄露。
- **[P1] 版本号单一来源**：构建脚本从 `package.json` 生成 `www/js/constants.js` 的 `APP_VERSION`，并同步写入 Android `versionName`；`versionCode` 递增规则文档化。
- **[P2] 补根 README**：命令表（`dev/build/desktop/android:release/sync`）、SCF 部署与环境变量、签名流程、发布 checklist。
- **[P2] 代理显式编码头**：`/image` 返回 `X-Encoding: binary|base64`，前端据此取消魔术字节猜测。

**验收**：代理模式下封面/角色/制作方全部正常；一条命令完成 `sync`；README 可指导他人从零构建与发版；`npm run check` 绿。

## 三、M1 结构偿债（v1.2，约 1 周）

目标：把 `events.js`（~1200 行）与 `renderer.js`（~980 行）拆成可维护的领域分片，并降低 `check-source` 对文件内字符串的脆弱依赖。

- **拆分 `events.js`** → `events/list.js`、`events/detail.js`、`events/form.js`、`events/settings.js`、`events/io.js`（导入导出）；`events/index.js` 聚合导出 `attach*`。
- **拆分 `renderer.js`** → `renderer/list.js`、`renderer/detail.js`、`renderer/form.js`、`renderer/settings.js`、`renderer/components.js`（卡片/星级/图片）；`renderer/index.js` 保留 `render()` 分发。
- **事件委托**：列表与详情交互改为在容器上委托绑定，减少每次全量渲染后的重复绑定与潜在多次触发。
- **测试扩面**：为 `changeProgress/deriveStatus`、`classifySeason` 跨年边界、`readBackup` 迁移、`getReminderItems`、`extractAnimationStudio` 补齐用例；新增 `events` 关键分支的可测纯函数。
- **弱化 check-source 字符串断言**：把 “代理按钮文案”“UTF-8 导出” 等断言迁移为对稳定导出函数/常量的检查，避免拆分后误报。

**验收**：单文件不超过 ~400 行；`npm run check` 绿；连续编辑观后感不失焦/不回退；列表 +1、筛选、导入导出手测无回归。

## 四、M2 本地优先纵深（v1.3，2～3 周）

目标：让 Bangumi 成为 “资料增强源” 而非运行依赖，并给追番用户一个 “今天看什么” 的入口。

### 4.1 元数据快照落库
- 选中/关联 Bangumi 条目时，把中文名、封面 URL、简介摘要、总集数**快照写入本地记录**（新增 `meta` 字段，升级 `SCHEMA_VERSION → 3` 并写迁移）。
- 后台按 TTL 刷新快照，失败时沿用旧值；允许用户 **解除关联 / 重新匹配 / 手动纠错**，且刷新不得覆盖用户手改字段。
- 详情页与封面列表优先读快照，离线仍可展示已缓存资料。

### 4.2 “今天”首页
- 将启动一次性提醒升级为稳定页面：**今日更新（追番，按 `updateWeekDay`）/ 待补进度（binge）/ 即将完结 / 最近更新**四区块。
- 复用 `core.getReminderItems`，扩展 “即将完结（剩余集数阈值）” 与 “最近 `updatedAt`” 派生。

### 4.3 schema v3 迁移能力
- `readBackup` 按 `schemaVersion` 逐版本迁移；写入失败提示；导入前自动本地备份、支持 “撤销最近一次导入”。

**验收**：断网进入任意已关联详情仍可见快照资料；今日首页正确分区；导入 v2 备份自动迁移为 v3 且用户手改不被刷新覆盖。

## 五、M3 观看日志（v2.0，3～4 周）

目标：把 “覆盖式进度” 升级为 “可回顾的观看历史”，形成产品差异化。

- **追加式观看事件**：在覆盖 `currentEpisode` 之外，追加 `events: [{episode, at}]` 事件流（新增字段 + 迁移），为统计提供可信数据源。
- **观看时间线**：按时间展示进度推进与单集笔记。
- **年度/季度回顾**：完成数、评分分布、年度最爱、可分享回顾卡。
- **单集笔记检索**：搜索总评与单集笔记，结果直达对应作品与集数。
- **可控本地通知**：接入 `@capacitor/local-notifications`，**默认关闭**，支持逐部开启、设定时间与静默；按本地计划触发，联网时校正条目信息。

**验收**：回顾统计与事件流一致；检索命中可跳转；通知仅对用户显式开启的作品触发、可关闭。

## 六、M4 规模化能力（v2.x，按需）

仅在实际需求出现后启动，避免过度设计。

- **存储升级**：当快照/事件流/统计索引显著增长、接近 localStorage 上限时，迁移 IndexedDB（保留导入导出兼容）。
- **加密备份**：先做 “加密备份到用户选定位置”，再评估实时同步。
- **可选云同步**：账号系统为可选层；冲突按 **记录 ID + 字段更新时间 + 删除标记** 处理，禁止按标题覆盖。
- **框架演进**：仅当页面数量/协作复杂度继续增长时，再评估渐进式 React/TypeScript 迁移。
