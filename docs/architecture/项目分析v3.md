# 追番记录 App — 项目解读分析 v3

> 生成时间：2026-07-18 ｜ 版本基线：v1.1.0（Android versionCode 2）
> 分析范围：Web 源码（ES Module）、Capacitor 配置、Android 工程、Electron 便携版、腾讯云函数代理、构建/测试/CI 与发布配置
> 配套文档：《后续升级计划书.md》

## 一、结论摘要

自 v2 分析（2026-06-30）以来，项目的**工程底座已基本补齐**：完成了 ES Module 化与 Vite 单一构建、`webDir` 统一为 `dist`、签名密钥与明文密码治理、Android 权限收敛、代理加固、单元测试与 CI 接入。此前 v2 判定的 P0/P1 阻塞项**大部分已闭环**。

当前阶段判断：**发布安全与数据健壮性已达到可持续迭代标准，剩余短板集中在“可维护性”（大文件未拆分）与“产品纵深”（观看日志/今日工作流/统计尚未开工）两处。**

换言之，"能不能放心发版" 的问题已基本解决；下一阶段的重心应从 "修地基" 转向 **"拆分巨型模块 + 沿本地优先观看日志方向做产品纵深"**。

## 二、架构总览（当前实际）

清晰的分层单向数据流：Web 内核（ES Module + Vite）+ 多端壳（Capacitor Android/iOS、Electron 便携版）。

```
app.js (启动/安全渲染兜底/全局错误/返回键/提醒)
  └─ store.js (state + setRenderer 回调解耦，仅存 currentAnimeId)
       ├─ renderer.js (视图模板/渲染 ~980 行)
       ├─ events.js   (事件绑定 ~1200 行，4 个 attach 入口)
       ├─ api.js      (Bangumi 客户端：超时/重试/去重/内存+持久化缓存/图片代理/编码兜底)
       ├─ core.js     (纯业务逻辑：状态推导/进度/季度归类/制作方提取)
       ├─ data.js     (记录规范化/校验/备份 schema v2)
       ├─ storage.js  (localStorage 封装 + storage-error 事件)
       ├─ constants.js / utils.js (escHtml / safeImageUrl)
```

| 层 | 职责 | 质量评价 |
|---|---|---|
| `core.js` / `data.js` | 纯函数业务逻辑与数据校验 | ⭐ 无副作用、可测试；`normalizeAnimeRecord` 对全字段裁剪/钳制/枚举校验 |
| `api.js` | 网络层 | ⭐ `AbortController` 超时、429/502/503/504 退避重试+抖动、并发去重、内存+持久化 TTL、stale-while-error、UTF-8 兜底 |
| `store.js` | 状态管理 | ⭐ 仅存 `currentAnimeId`（从列表派生记录），写操作返回布尔值，`setState({render})` 可控渲染 |
| `scf_bangumi_proxy.js` | 云函数代理 | ⭐ CORS 白名单、路径白名单、body/响应大小限制、`/image` 图片代理带 host+path 校验 |
| `electron/main.cjs` | 桌面壳 | ⭐ `contextIsolation`/`sandbox` 开启、`nodeIntegration` 关闭、外链走系统浏览器 |
| `events.js` / `renderer.js` | 事件层/视图层 | ⚠ 分别约 1200 / 980 行，单文件职责过载，是当前最大可维护性债务 |
| 工程化 | Vite / 测试 / 校验脚本 / CI | ⭐ 6 组单测 + `check-source`/`check-dist` 守护安全不变量 + GitHub Actions |

## 四、当前问题与风险（按优先级）

### 🔴 P0-1 线上云函数与签名身份仍需运维核对（代码之外的风险）

代码层面已就绪，但两项**无法从仓库验证**、仍可能导致线上故障或升级失败：

1. **线上 SCF 是否为最新版**：前端 `api.js` 强依赖代理的 `/image`（`lain.bgm.tv` 图片代理）与 `/v0/subjects/{id}/persons`。若线上仍是旧版本，代理模式下将**封面/角色裂图**、**制作方提取失败**。部署后需自测：`GET /v0/subjects/565802/persons`、`GET /image?url=<lain.bgm.tv 图片>` 均应 200，并确认 `ALLOWED_ORIGINS` 含 `https://localhost`（Capacitor Android WebView origin）。
2. **签名身份一致性**：历史上曾用弱口令 `123456` 的 keystore 构建过 v1.1 APK。当前 `keystore.properties` 已改强口令，但**若与线上分发指纹不一致，老用户无法覆盖升级**。需确定唯一权威签名密钥，并用 `git filter-repo`/BFG 清理历史中残留的弱口令 keystore（现工作树已 gitignore，但历史提交可能仍含密钥，应视为已泄露）。

### 🟠 P1-1 `events.js`（~1200 行）/ `renderer.js`（~980 行）仍未拆分

v2 P1-1 尚未落实。`events.js` 现有 4 个入口 `attachListEvents / attachDetailEvents / attachFormEvents / attachSettingsEvents`，仍混合列表、详情、番剧加载、单集编辑器、表单、导入导出、设置多类逻辑；`renderer.js` 同样按视图聚在单文件。这是当前**最大的可维护性债务**：改动易牵连、评审成本高、`check-source` 也已针对该文件写了字符串断言（脆弱耦合）。建议按视图拆分为 `events/{list,detail,form,settings,io}.js`、`renderer/{list,detail,form,settings}.js`，保留聚合入口。

### 🟠 P1-2 版本号仍为三处手工维护

`package.json` / `constants.APP_VERSION` / `android/app/build.gradle`（`versionName`+`versionCode`）当前一致（均 `1.1.0`），但缺少单一来源与构建期注入，后续极易漂移。建议以 `package.json` 为唯一来源，构建时生成 `constants` 并同步 Android 版本。

### 🟡 P2-1 图片二进制/Base64 判定仍靠启发式

`resolveBangumiImageUrl` 依赖魔术字节判断二进制、否则按 Base64 解码。虽有正则兜底，仍偏脆弱。代理已返回 `X-Content-Type-Options: nosniff`，建议进一步返回显式 `X-Encoding` 头，让前端不再猜测。

### 🟡 P2-2 缺少项目 README 与发布手册

仓库根目录仍无 README。`dev/build/desktop/android:release/sync` 命令、SCF 部署与环境变量、签名密钥流程均散落在脚本中，维护心智高。建议补一份根 README + 发布 checklist。

### 🟡 P2-3 schema 版本化 “有版本、无迁移”

`SCHEMA_VERSION = 2` 已写入备份，但 `readBackup` 只做规范化，未按 `schemaVersion` 做版本化迁移，也无 “最近一次导入撤销 / 自动备份” 能力。当前字段稳定时风险低，但一旦引入元数据快照/统计索引，需要真正的逐版本迁移。

## 五、产品纵深现状（尚未开工，方向仍成立）

v2 与前序文档提出的产品方向**均未落地**，仍是下一阶段最有差异化的投入：

- **“今天”首页**：启动仍是一次性提醒（`showReminder`），未升级为 “今日更新 / 待补进度 / 即将完结 / 最近记录” 的稳定页面。
- **元数据快照**：详情/封面仍每次远程拉取（已有 TTL 缓存与 `getCachedBangumiSubject`），但未把中文名/封面/简介/总集数**快照进本地记录**，第三方故障时体验仍退化。
- **观看时间线 / 年度回顾 / 统计**：未实现。当前 `currentEpisode` 为覆盖式，缺少追加式观看事件，统计可信度受限。
- **单集笔记检索**：未实现。
- **可控本地通知**：未接入 Capacitor Local Notifications。
- **可选云同步**：未开始（应在本地 schema/冲突策略稳定后再做）。

## 六、总体判断

v3 阶段的 Anime Tracker 已经跨过 “可放心发布” 的门槛：**构建、密钥、数据边界、状态一致性、网络健壮性、质量门禁**六个底座维度均已达标。剩余风险要么在仓库之外（线上部署/签名核对），要么是可维护性债务（巨型文件）与尚未开工的产品纵深。

下一阶段目标应明确为两条并行主线：**(1) 偿还 `events.js`/`renderer.js` 的结构债；(2) 沿 “本地优先观看日志” 做出今日首页、元数据快照与回顾统计等差异化能力。** 具体排期见配套《后续升级计划书.md》。
