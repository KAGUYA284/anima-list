# 追番记录 App — 项目解读分析与改进建议 v2

> 生成时间：2026-06-30 ｜ 版本基线：v1.1.0

## 一、架构总览

当前已是清晰的分层单向数据流架构（Web 内核 + Capacitor/Electron 多端壳）：

```
app.js (启动/全局错误/返回键)
  └─ store.js (state + setRenderer 回调解耦)
       ├─ renderer.js (渲染视图 817行)
       ├─ events.js  (事件绑定 1156行)
       ├─ api.js     (Bangumi 客户端: 缓存/重试/超时/图片代理)
       ├─ core.js    (纯业务逻辑: 状态推导/季度归类/制作方提取)
       ├─ data.js    (记录规范化/校验/备份 schema)
       ├─ storage.js (localStorage 封装 + 错误事件)
       ├─ constants.js / utils.js
```

| 层 | 职责 | 质量评价 |
|---|---|---|
| `core.js` / `data.js` | 纯函数业务逻辑与数据校验 | ⭐ 可测试、无副作用，设计优秀 |
| `api.js` | 网络层 | ⭐ 重试退避+抖动、超时、并发去重、内存+持久化缓存、stale-while-error、编码兜底 |
| `store.js` | 状态管理 | ⭐ `setRenderer` 解耦渲染，写操作返回布尔值 |
| `events.js` | 事件层 | ⚠ 单文件 1156 行，职责过载 |
| 工程化 | Vite/测试/校验脚本 | ⭐ `check-source.mjs` 用断言守护安全不变量 |

## 二、相较 v1 的关键进步

1. **模块化**：从全局函数改为 ES Module + Vite 打包，`webDir: dist`
2. **测试**：新增 6 组单测（core/data/api/store/utils/proxy）+ `npm run check` 全链路校验
3. **数据健壮性**：`normalizeAnimeRecord` 对所有字段裁剪/钳制，schema 版本化，`escHtml` + `safeImageUrl`(仅 https) 防 XSS
4. **安全治理**：签名密钥已移出 Git 跟踪、改用强口令 `keystore.properties`(已 gitignore)、`check-source` 禁止明文密码/危险 Manifest 标志
5. **SCF 代理加固**：CORS 来源白名单、请求路径白名单、请求/响应体大小限制、新增 `/image` 图片代理与 `/persons` 端点
6. **错误 UX**：启动页兜底、渲染 try/catch、全局 `unhandledrejection`/`error`、存储失败 Toast

## 三、问题与改进建议（按优先级）

### 🔴 P0-1 线上腾讯云函数必须重新部署

前端 `api.js` 已**强依赖**本地最新 `scf_bangumi_proxy.js` 的两个新能力，线上旧版本会直接失效：

| 前端调用 | 依赖端点 | 线上旧版缺失后果 |
|---|---|---|
| `getBangumiImageUrl` → `/image?url=` | `/image` 图片代理 | 代理1模式下**角色/封面图全部裂图** |
| `getBangumiPersons` → `/v0/subjects/{id}/persons` | persons 端点 | **动画制作方提取失败** |

**部署清单**：
1. 用当前 `scf_bangumi_proxy.js` 覆盖线上函数代码
2. 配置环境变量 `ALLOWED_ORIGINS`，加入 `https://localhost`（Capacitor Android 的 WebView origin）
3. 部署后自测：`GET /v0/subjects/565802/persons`、`GET /image?url=<lain.bgm.tv 图片>` 均应 200

### 🔴 P0-2 签名身份一致性风险

上一轮曾用弱口令 `123456` 的 `release.keystore` 构建并签名了 v1.1 APK；现在 `keystore.properties` 已改为强口令新密钥。**若二者是不同密钥，签名指纹不一致 → 老用户无法覆盖升级**（Android 会拒绝安装）。

**建议**：确定唯一权威签名密钥；今后所有正式版必须用同一 keystore；因弱口令密钥已进入 Git 历史，建议用 `git filter-repo`/BFG 清理历史并确认该密钥不再作为线上签名。

### 🟠 P1-1 拆分 `events.js`（1156 行）

当前混合了列表、导出(筛选/分组/文本/文件)、导入、详情、番剧详情加载、单集编辑器、表单、设置八类逻辑。建议按视图拆分为 `events/list.js`、`events/export.js`、`events/detail.js`、`events/form.js`、`events/settings.js`，`attach*` 作为入口聚合。

### 🟠 P1-2 引入 CI

已有 `npm run check`（lint+test+build+check:dist）但无 CI 配置。建议加 `.github/workflows` 在 push/PR 时自动跑，防止回归（如再次误用 `TextDecoder` 或误提交明文密码）。

### 🟡 P2 其他

- **补 README**：记录 `dev/build/android:release/desktop` 命令与 SCF 部署步骤、环境变量，降低维护心智
- **版本号集中化**：`package.json` / `constants.APP_VERSION` / `build.gradle` 三处均为 `1.1.0`（当前一致 ✓），建议构建时由 `package.json` 生成 `constants` 避免漂移
- **编码兜底冗余提示**：`apiFetchWithEncodingFallback` + `hasBrokenEncoding`(检测 U+FFFD 回退直连) 是很好的防线；线上重新部署后旧的分块截断问题不再出现，该路径将成为纯保险
- **图片 base64 启发式**（`api.js` 内）：靠魔术字节判定二进制、否则当 base64，虽有正则校验，仍偏脆弱，可让代理统一返回明确的 `X-Encoding` 头以消除猜测
