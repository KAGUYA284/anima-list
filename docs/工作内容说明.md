# Anima List 工作内容说明

本文件按版本累计记录更新内容。后续版本在文件顶部追加新的版本章节，不再为每个版本创建单独文件。

## v1.2.0

更新时间：2026-08-05（UTC+08:00）

### 更新内容

- 调整追番季度归类：处于“在看”状态时，根据系统日期和每周一集的播出进度跨季度移动；归类日期不会超过末集预计播出日期；已看完后回到首播季度。
- 调整补番季度归类：处于“在看”状态时随系统季度移动；已看完后按照实际看完日期归档。
- 统一想看、搁置及其他非活跃状态的归类方式，按照番剧首播季度归档。
- 补番进入“已看完”状态时自动记录当天日期；重新改为未完成状态时清除旧的看完日期。
- 修复想看状态的追番无法收到更新提醒的问题，并限制提醒只在实际播出周期内出现。
- 将列表展示与导出筛选统一接入同一套季度分组逻辑，避免不同入口得出不同季度。
- 为追番增加“每周更新时间”手动选择项。放送日期变化时仍会自动推断星期，但用户可以根据实际更新时间改为周一至周日中的任意一天。
- 将软件版本统一升级为 v1.2.0，并将 Android `versionCode` 从 2 递增到 3。
- 统一 Web、Windows 和 Android 的软件名称为 `Anima List`。
- 清理旧 PC 导出包中误带的 Capacitor/Android 构建缓存，并在导出流程中排除 `node_modules` 和常见运行时缓存目录。
- 增加 Windows NSIS 安装版本，与便携版共同维持 v1.2.0。
- 清理项目中的依赖缓存、构建中间目录、Capacitor 同步产物、IDE 配置、系统元数据和无引用旧辅助脚本，同时保留正式发布产物与 Android 签名密钥。
- 将清理后的 v1.2.0 项目状态作为 `master` 主线上的新本地 Git 节点保存，不改写既有提交。
- 将发布产物统一整理到 `发布版本/v1.2.0/`，按 Windows 安装版、正式免安装版、缓存测试版、Android 和 Web 分类存放。
- 增加正式无缓存免安装包，以及把缓存、Local Storage 和 IndexedDB 固定保存在解压目录 `test-user-data/` 的免安装测试包。
- 增加无需 Node.js 的网页版启动器，使用 Windows PowerShell 在本机回环地址提供静态页面服务。
- 增加 `release:package` 和 `release:all` 命令，使后续修改可按同一流程同步生成和归档多端产物。
- 整理项目根目录：移除重复图片和旧开发启动器，将历史架构分析归入 `docs/architecture/`，并同步更新开发及发布路径说明。
- 修复发布版网页启动器双击后无反应的问题，将批处理文件统一为纯 ASCII 和 Windows CRLF 换行格式。
- 增加“更新时间来源”设置，可在“1. 长门有希”和“2. bangumi”之间切换；默认使用长门有希数据，并保留原 Bangumi 方式作为可选来源和查询失败时的降级信息。
- 增加具体到小时的每周更新时间字段，支持常规 `HH:MM` 以及日本深夜档使用的 `24:00` 至 `29:59` 表示法，并在表单、列表、详情和提醒中统一显示。
- 在腾讯云函数代理中增加 `/yuc/anime` 接口，抓取 `yuc.wiki` 对应季度页面，通过封面、中日文标题归一化和相似度匹配建立数据映射，并使用六小时缓存减少抓取频率。
- 增加“显示番剧具体信息”设置开关；开启后从长门有希季度页显示原作、导演、副导演、编剧、人物设计、动画人设和动画制作。
- 加固长门有希页面解析：仅允许固定主机和季度路径，限制响应体积和请求时间，只输出白名单纯文本字段，不执行或透传远端 HTML。
- 增加长门有希页面解析、标题映射、季度计算、具体更新时间清洗等自动化测试，并在源码检查中守卫新增代理路由和设置项。
- 已完成云函数新版源码，并将客户端调整为优先在 Electron 端通过 Node.js 直接抓取 yuc.wiki、浏览器/移动端在可用时直接抓取，失败后才回退到云函数；新增季度列表 `/yuc/season` 云函数接口作为兼容降级。当前线上探测到的云函数仍为旧版本，`/yuc/season` 尚未上线，需要在有腾讯云部署权限时重新部署本文件。
- 放送日期、每周更新时间和时间段统一读取 yuc.wiki，并显示具体时间及“上午、下午、晚间、深夜”时段；应用启动列表时会自动同步已有追番记录的 yuc 日期和时间信息。
- 移除 Bangumi 原有角色/声优区域下的“动画制作”行，避免与 yuc.wiki 制作信息重复；yuc 制作信息仍独立显示。
- 在设置按钮右侧增加扁平化日历图标的新番表入口，可切换每个季度的 yuc.wiki 新番表，并直接将番剧加入“想看”列表。
- Windows 正式免安装版和缓存测试版改为未压缩目录交付；缓存测试版使用随包 `test-user-data` 隔离浏览器缓存、Local Storage 和 IndexedDB，首次启动创建缓存，后续启动复用缓存。

### 发现的问题

- 列表渲染与导出筛选原先各自维护季度归类逻辑，容易出现同一部番在不同功能中被分到不同季度的问题。
- 追番原先始终按照首播日期归类，无法表现跨季度播出的进度。
- 补番原先始终按照开始观看日期归类，不能随系统时间移动，也不能在完成后按照看完日期固定归档。
- 补番通过进度按钮完成时不会自动填写看完日期，导致按看完季度归档缺少可靠数据。
- 0 集进度会被自动识别为“想看”，但提醒逻辑只接受“在看”，因此新添加且尚未观看的连载番不会提醒。
- 部分番剧的首播日期与后续固定更新时间不是同一星期，原先保存时总是根据首播日期重新计算，无法记录真实更新时间。
- Electron Builder 会自动收集 `package.json` 中的生产依赖，导致旧便携包把 Android 依赖的 `build/.transforms`、`intermediates` 等缓存一并带入。
- 旧的根目录 `启动PC版.cmd` 实际启动 Vite 开发服务器，既依赖 Node.js，又不适合作为交付给普通用户的网页版启动器。
- 根目录 `1.png` 与 `www/1.png` 内容完全相同，属于重复文件；历史分析文档也与日常开发文档混放，降低了目录可读性。
- 网页启动器最初以无 BOM 的 UTF-8 和 LF 换行发布，`cmd.exe` 在部分 Windows 本地代码页下会错误拆分命令，导致窗口立即退出。
- `yuc.wiki` 的首播时间卡片与制作信息卡片位于不同 HTML 区域，不能依靠 DOM 顺序稳定关联，需要优先使用相同封面 URL，再用标准化中日文标题做保守匹配。
- `yuc.wiki` 当前 HTTPS 证书已过期，Node.js 默认安全校验会拒绝直接抓取其 HTTPS 页面。
- 清理后的本机缺少 Android SDK 与 `android/local.properties`，首次同步 Android 发布版时无法找到 API 35 平台，需要临时恢复官方命令行 SDK 才能完成构建。

### 当前问题

- Android 当前仍可正常构建，但 Gradle 报告部分依赖使用了弃用特性；未来升级到 Gradle 9 前需要先升级或调整对应的 Capacitor/Gradle 依赖。
- Windows 安装包目前没有可用的代码签名证书，安装器可以正常使用，但首次运行可能出现 Windows SmartScreen 提示。
- `npm audit` 当前报告 9 个间接依赖漏洞（2 个中危、6 个高危、1 个严重）；修复建议涉及依赖升级，本次保持 v1.2.0 功能范围，未执行可能产生破坏性变更的 `npm audit fix --force`。
- 本地云函数源码已更新；端侧直抓失败时会回退到 `/yuc/anime` 或 `/yuc/season`。当前线上 `/yuc/anime` 可访问但 `/yuc/season` 返回 404，需要重新部署后季度新番表的云函数降级路径才会生效。
- `yuc.wiki` HTTPS 证书当前过期；代理暂时从同一固定主机公开提供的 HTTP 页面读取并只解析白名单文本。证书恢复后应切回 HTTPS 抓取。

### 踩过的坑

- 不能直接用当前系统季度无限移动追番，否则已经停止播出但尚未看完的番剧会一直跟随年份和季度漂移；因此需要用预计末集播出日期作为上限。
- JavaScript 的 UTC 日期格式化在部分时区可能把本地日期偏移到前一天，因此季度归类和自动完成日期均使用本地年月日。
- “想看”提醒不能只放宽状态判断，还要校验首播日期和预计末集日期，否则会在开播前或播完后产生错误提醒。
- 手动更新时间不能只增加选择框；保存逻辑也必须优先读取选择值，否则仍会被首播日期推断结果覆盖。
- 备份格式测试原先写死了 v1.1.0；升级应用版本后必须同步测试期望值，否则功能正常但发布检查仍会失败。
- Android SDK 路径在 `local.properties` 中使用 Gradle 转义格式（例如盘符冒号写成 `\:`）；发布校验脚本读取后需要先还原转义，才能正确找到 `apksigner`。
- Windows 下如果旧版 PC 可执行文件正被进程映射，覆盖同步会短暂失败；需要待文件锁释放后单独重试 EXE，并重新校验 EXE 与 `app.asar`。
- 仅在压缩后删除缓存不可靠；必须同时从 Electron Builder 的文件规则排除移动端依赖，并在便携版整理脚本中执行二次清理。
- 统一展示名称时不能同时修改 Android applicationId、Electron appId 和既有本地存储键，否则会破坏应用升级关系或让已有数据不可见；这些内部兼容标识继续保留旧值。
- 项目已有大量未提交文件和发布产物，发布同步时需要保留现有源码改动，并只刷新明确指定的 PC、Android 产物。
- 缓存测试版不能只预置一份随机缓存；需要让 Electron 在启动早期切换 `userData` 路径，并用随包标记区分正式版和测试版，否则两者仍会读写系统用户目录中的同一份数据。
- 网页版不能直接双击 `index.html`，浏览器对 ES Module 和本地文件协议有限制；发布包必须通过本机 HTTP 服务启动。
- Windows PowerShell 5 会把不带 BOM 的 UTF-8 脚本按本地代码页解析；包含中文路径时甚至可能产生伪语法错误，因此发布用 `.ps1` 文件需要保存为带 BOM 的 UTF-8。
- Windows 批处理与 PowerShell 脚本的编码要求不同：`.ps1` 使用带 BOM 的 UTF-8，`.cmd` 则应避免本地化文本并使用纯 ASCII + CRLF，才能稳定支持双击启动。
- 日系电视播出时间常以 `25:30` 等“超过 24 点”格式记录，若只接受浏览器原生 `time` 输入的 `00:00` 至 `23:59` 会丢失真实时刻，因此需要文本输入和 `00:00` 至 `29:59` 的显式校验。
- 不能为绕过过期证书关闭 Node.js TLS 校验；当前采用固定 HTTP 主机、固定路径、响应大小限制和白名单纯文本解析，把风险约束在代理端，待证书恢复后再切回 HTTPS。
- Android `aapt` 在当前 Windows 本地代码页下不能可靠读取含中文目录的 APK 路径；产物本身不受影响，校验应用名称和版本时需要先复制到纯 ASCII 临时路径，完成后立即删除临时副本。
- 压缩包不能可靠保留空的 `test-user-data` 目录，且测试版首次运行本来就没有历史缓存；改为未压缩目录交付，并由 Electron 在首次启动时创建、后续复用该目录。
- yuc.wiki 季度表中的播出时间卡片与制作信息卡片分离，季度表必须先解析所有时间卡片，再通过封面或标题映射制作信息，不能只遍历制作卡片。
