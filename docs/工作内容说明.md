# Anima List 工作内容说明

本文件按版本累计记录更新内容。后续版本在文件顶部追加新的版本章节，不再为每个版本创建单独文件。

## v1.3.0

更新时间：2026-08-23（UTC+08:00）

### 更新内容

- 新增 Cloudflare Workers、Hono、D1 TypeScript 云同步服务，提供注册、登录、获取快照、revision 条件写入、409 冲突和全部会话撤销接口。
- 新增可重复执行的 `0001_initial.sql` 迁移，按用户隔离账号与完整 JSON 快照，分别保存数据结构版本、应用版本、客户端时间、服务端时间、SHA-256 哈希和服务端修订号。
- 密码改为 PBKDF2-HMAC-SHA-256：每用户随机 16 字节盐、210,000 次迭代和 32 字节派生值；比较使用恒定时间逻辑，数据库不保存明文或单次 SHA-256。
- JWT 使用 HS256，校验签名、签发方、受众、过期时间和数据库 `token_version`；密钥只允许通过 `wrangler secret put JWT_SECRET` 注入。
- 认证路由增加请求大小、邮箱、12–128 字符密码与实例内限流；响应与日志不暴露密码、哈希、Token 或账号存在性。
- 同步快照限制为 1 MB，验证 JSON 对象、数据版本、修订号、毫秒时间、嵌套深度、节点和数组长度；D1 使用带旧 revision 的条件更新防止并发覆盖。
- 客户端新增统一 SyncService 和存储适配层；每次本地修改写入 dirty、最后修改时间、数据版本及兼容键，联网后自动尝试同步。
- 同步决策只依据服务端 revision 和本地 dirty 状态；客户端时间不参与覆盖判断，上传响应丢失时可用相同内容哈希安全确认结果。
- 设置页新增云同步服务地址、注册、登录、立即同步、退出和状态展示；并发冲突必须选择使用云端、明确确认本地覆盖，或导出双方 JSON。
- 云同步服务地址改为无重绘保存，并在注册或登录前再次校验提交，避免输入框失焦重绘导致首次点击失效。
- Web MVP Token 使用 localStorage；Electron 使用 `safeStorage` 系统凭据加密并通过主进程请求 Worker；Android 新增基于 Android Keystore AES-GCM 的原生安全存储插件。
- 增加 Worker TypeScript、PBKDF2/JWT、快照验证、revision 冲突及客户端同步决策测试，并提供不含真实数据库 ID 和密钥的部署说明。
- 版本升级为 v1.3.0，Android `versionCode` 从 4 递增到 5，并同步 Web、Electron、Android 与发布目录。

### 发现的问题

- Electron 打包版页面使用 `file://`，直接从渲染进程请求 Worker 无法使用普通浏览器 Origin 白名单；需要通过隔离的主进程 IPC 发起受 HTTPS 与 `/api/` 路径约束的请求。
- 仅在客户端提交前读取 revision 仍存在检查后写入竞争窗口；D1 更新语句本身也必须包含 `WHERE revision = ?` 并检查实际变更数。
- 客户端上传成功但响应丢失时，本地仍为 dirty 且云端 revision 已领先；若不比较规范化快照哈希，会把同一份数据误判为人工冲突。
- 设置页原先在保存同步服务地址时立即重绘整个页面，会替换用户正要点击的登录按钮，并可能使异步事件结束后拿不到原按钮引用。

### 当前问题

- 生产 Cloudflare D1 数据库、域名、Origin 白名单和 `JWT_SECRET` 尚未由用户提供，因此本次只完成可部署代码、迁移和本地测试，未执行线上建库、迁移或部署。
- MVP Access Token 有效期为 7 天，尚未实现 Refresh Token；实例内限流不能替代 Cloudflare 生产环境的 Rate Limiting/WAF。
- Android 模拟器、Android 真机及实际移动网络切换需要在有对应设备的环境继续验收；自动化测试已覆盖共享同步状态机和安全服务逻辑。

### 踩过的坑

- `client_updated_at` 只能用于展示，不能决定覆盖顺序；设备时间错误或被人为调整时，只有服务端 revision 能可靠发现并发写入。
- 云端冲突不能通过“最后写入获胜”自动消解，本地强制覆盖必须先重新读取最新 revision，并在用户明确确认后提交。
- 同步快照不能直接使用带动态 `exportedAt` 的普通导出文件，否则内容哈希每次都会变化；同步采用只包含 schemaVersion 和 records 的稳定快照。
- Token 不能跟随普通设置导出：Electron 与 Android 分别使用系统加密能力，Web localStorage 只作为首版兼容方案。
- 异步按钮事件不能在 `await` 后继续依赖 `event.currentTarget`；应提前保存按钮引用，同时避免输入设置保存时重绘整个表单。

## v1.2.1

更新时间：2026-08-06、2026-08-23（UTC+08:00）

### 更新内容

- 更新时间与放送日期统一使用 yuc.wiki，移除设置中的更新时间来源选项；Bangumi 继续负责搜索、封面、角色和声优资料。
- 增加具体到小时的每周更新时间字段，支持常规 `HH:MM` 以及日本深夜档使用的 `24:00` 至 `29:59` 表示法，并在表单、列表、详情和提醒中统一显示。
- 增加“显示番剧具体信息”设置开关；开启后从 yuc.wiki 季度页显示原作、导演、副导演、编剧、人物设计、动画人设和动画制作。
- 在腾讯云函数代理中增加 `/yuc/anime` 与 `/yuc/season` 接口，抓取 yuc.wiki 对应季度页面，通过封面、中日文标题归一化和相似度匹配建立数据映射，并使用六小时缓存减少抓取频率。
- 将客户端调整为 Electron 端直接抓取、Web/Android 端在环境允许时直接抓取 yuc.wiki，失败后才回退云函数；抓取只解析白名单纯文本字段。
- 放送日期、每周更新时间和时间段统一读取 yuc.wiki，并显示具体时间及“上午、下午、晚间、深夜”时段。
- 移除 Bangumi 原有角色/声优区域下的“动画制作”行，避免与 yuc.wiki 制作信息重复；角色和声优信息继续由 Bangumi 提供。
- 在设置按钮右侧增加扁平化日历图标的新番表入口，并显示 yuc.wiki 的季度番剧图片。
- 新番表改为按周一至周日分组；解析页面星期标题，使缺少首播日期但仍在连载的番剧也能归入正确星期。
- 新番表增加独立的年份和季度筛选器，年份不设置上限；yuc.wiki 数据边界设为 2019 年 10 月，更早季度统一显示“无数据”。
- 从新番表加入待看前，通过 Bangumi 代理搜索并保存匹配到的 `bgmId`，恢复主列表封面以及详情页角色、声优等 Bangumi 信息。
- 新番表匹配 Bangumi 时优先使用 yuc.wiki 日文标题；日文标题没有匹配结果后，再使用中文标题搜索兜底。
- 从新番表加入待看后保留在当前新番表页面，并即时把按钮更新为“已在待看列表”。
- 对 2019 年 10 月前的番剧停止请求 yuc.wiki，并隐藏具体时间段和 yuc.wiki 制作信息；Bangumi 基础资料仍可正常显示。
- 修复历史新番表把 `date_title`、`date_title1/2` 误判为空标题的问题，并过滤无法取得任何标题的异常条目，不再显示“未命名番剧”。
- 修复历史季度条目只有“全 N 话”而没有首播日时，从新番表加入后落入“未分类年”的问题；依次使用 yuc 首播日、Bangumi 首播日和所选季度首日归类。
- 搜索选择追番时始终查询 yuc.wiki 并自动填写具体更新时间，不再受旧版来源设置影响；列表载入时也会为已有追番补全缺失的 yuc 放送信息。
- 移除新番表端侧/云函数来源提示行和制作信息区域的“来源：长门有希”标注。
- 没有既有用户设置时默认使用封面列表模式，保留用户手动切换为仅文字模式的能力。
- JSON 导入完成后自动检查缺失字段，通过 Bangumi 补充条目 ID、集数和首播日期，再通过 yuc.wiki 补充更新星期、具体时间与时段；仅填空值并把结果批量保存到本地，单条查询失败不影响其他记录。
- 扩大“复制纯文字”导出结果弹窗和文本预览区，使用固定的可视高度及滚动区域，不再因隐藏状态下测量高度而缩成单行。
- “显示番剧具体信息”关闭时不再创建或请求 Bangumi 详情区域，因此封面摘要、角色、声优和 yuc 制作信息均停止展示。
- 增加列表“展示次序”设置及圆形说明按钮：时间次序保持原周一至周日顺序；更新次序从系统当天开始轮转，同日按上午、下午、晚间、深夜以及具体更新时间排序。
- 调整“更新次序”为优先显示最近已经更新的番剧：从昨天开始向前倒排星期，例如周三依次展示周二、周一、周日；同一天优先展示较晚的时段和更新时间。
- 在设置的数据管理区域增加“清空所有番剧”，执行前显示包含当前番剧数量的不可撤销确认，清空后保留设置页和用户设置。
- 新番表加入待看时先以 yuc.wiki 日文标题搜索 Bangumi，再读取完整 Bangumi 条目；导入规范中文/日文标题、集数、首播日期和 `bgmId`，并以 `bgmId` 优先拦截名称不同的重复番剧；无法匹配时不写入不完整记录。
- 主页番剧卡片支持触屏左滑及桌面鼠标左拖，展开扁平化扳手编辑和叉号删除操作；详情页的编辑、删除按钮同步为相同图标。
- Windows 正式免安装版和缓存测试版改为未压缩目录交付；缓存测试版使用随包 `test-user-data` 隔离并复用浏览器缓存、Local Storage 和 IndexedDB。
- 版本升级为 v1.2.1，Android `versionCode` 从 3 递增到 4，并同步更新 Web、Electron、Android 和发布目录。

### 发现的问题

- 新番表添加记录时没有保存 `bgmId`，因此主列表封面与详情页 Bangumi 角色、声优加载条件均不会触发。
- yuc.wiki 不同年份使用了多种番剧标题 CSS 类名，旧解析器只识别带下划线的变体，导致历史季度条目标题全部为空。
- yuc.wiki 历史季度会把首播日期替换为“全 N 话”等完结信息，不能仅依赖季度页当前文本保存首播日期。
- 纯文字导出弹窗原先在隐藏状态下读取文本框 `scrollHeight`，浏览器只能得到接近单行的高度，导致打开后几乎看不到 JSON 内容。
- 旧版“显示番剧具体信息”只控制 yuc 制作信息，Bangumi 角色与声优加载路径没有使用同一个开关。
- yuc.wiki 的首播时间卡片与制作信息卡片位于不同 HTML 区域，需要通过封面或标准化标题映射；部分连续播出条目没有首播日期，还需要读取页面星期分组标题。
- yuc.wiki 当前 HTTPS 证书已过期，Node.js 默认安全校验会拒绝直接抓取其 HTTPS 页面。
- 仅按 yuc.wiki 中文标题判断新番表重复项时，同一番剧若采用了不同译名，可能再次加入列表；需要在 Bangumi 匹配完成后按稳定的 subject ID 二次检查。

### 当前问题

- 本地云函数源码已更新；当前线上 `/yuc/anime` 可访问但 `/yuc/season` 返回 404，需要重新部署后 Web/Android 的季度新番表云函数降级路径才会生效。
- yuc.wiki HTTPS 证书当前过期；Electron 与代理暂时从同一固定主机公开提供的 HTTP 页面读取并只解析白名单文本。证书恢复后应切回 HTTPS 抓取。

### 踩过的坑

- 新番表只保存 yuc.wiki 标题并不足以恢复 Bangumi 封面和声优；必须先搜索并持久化 Bangumi subject ID，后续详情请求才有稳定的关联键。
- 解析 yuc.wiki 不能把某一个季度观察到的 CSS 类名当作固定结构；标题选择器需要兼容 `date_title` 及其数字、下划线变体，并在输出层再次拒绝空标题。
- 历史季度的“全 N 话”不是日期；添加记录时必须复用 Bangumi 匹配结果中的首播日，并准备季度首日兜底，才能保证记录不会进入未分类年份。
- 导入数据经过规范化后，缺失集数会变成 1，不能只检查字段是否为空；补全过程需要把 1 视为可能的占位值，但只在 Bangumi 明确返回更大集数时替换。
- 异步补全不能直接覆盖任务开始时的整份列表，否则用户在查询期间的编辑会丢失；完成时必须以最新本地列表为基准，只合并仍然缺失的字段。
- 左滑操作不能只监听触摸事件，否则 Electron 桌面端无法使用；统一使用 Pointer Events，并区分横向拖动、纵向滚动和普通点击，才能避免滑动后误入详情页。
- 不能只从首播日期计算星期，因为“全 24 话”“泡面”等条目可能不提供日期；需要按 DOM/HTML 顺序继承最近的周一至周日分组标题。
- 日系电视播出时间常以 `25:30` 等“超过 24 点”格式记录，不能使用只接受 `00:00` 至 `23:59` 的原生时间输入。
- 不能为绕过过期证书关闭 Node.js TLS 校验；当前使用固定主机、固定路径、响应大小限制和白名单解析约束风险。
- 压缩包不能可靠保留空的 `test-user-data` 目录；未压缩目录能让缓存测试版首次启动创建、后续稳定复用缓存。

## v1.2.0

更新时间：2026-08-05（UTC+08:00）

### 更新内容

- 调整追番季度归类：处于“在看”状态时，根据系统日期和每周一集的播出进度跨季度移动；归类日期不会超过末集预计播出日期；已看完后回到首播季度。
- 调整补番季度归类：处于“在看”状态时随系统季度移动；已看完后按照实际看完日期归档。
- 统一想看、搁置及其他非活跃状态的归类方式，按照番剧首播季度归档。
- 补番进入“已看完”状态时自动记录当天日期；重新改为未完成状态时清除旧的看完日期。
- 修复想看状态的追番无法收到更新提醒的问题，并限制提醒只在实际播出周期内出现。
- 将列表展示与导出筛选统一接入同一套季度分组逻辑，避免不同入口得出不同季度。
- 为追番增加“每周更新时间”手动选择项。放送日期变化时仍会自动推断星期，但用户可以根据实际更新时间改为周一至周日中的任意一天。
- 将软件版本统一升级为 v1.2.0，并将 Android `versionCode` 从 2 递增到 3。
- 统一 Web、Windows 和 Android 的软件名称为 `Anima List`。
- 清理旧 PC 导出包中误带的 Capacitor/Android 构建缓存，并在导出流程中排除 `node_modules` 和常见运行时缓存目录。
- 增加 Windows NSIS 安装版本，与便携版共同维持 v1.2.0。
- 清理项目中的依赖缓存、构建中间目录、Capacitor 同步产物、IDE 配置、系统元数据和无引用旧辅助脚本，同时保留正式发布产物与 Android 签名密钥。
- 将清理后的 v1.2.0 项目状态作为 `master` 主线上的新本地 Git 节点保存，不改写既有提交。
- 将发布产物统一整理到 `发布版本/v1.2.0/`，按 Windows 安装版、正式免安装版、缓存测试版、Android 和 Web 分类存放。
- 增加正式无缓存免安装包，以及把缓存、Local Storage 和 IndexedDB 固定保存在解压目录 `test-user-data/` 的免安装测试包。
- 增加无需 Node.js 的网页版启动器，使用 Windows PowerShell 在本机回环地址提供静态页面服务。
- 增加 `release:package` 和 `release:all` 命令，使后续修改可按同一流程同步生成和归档多端产物。
- 整理项目根目录：移除重复图片和旧开发启动器，将历史架构分析归入 `docs/architecture/`，并同步更新开发及发布路径说明。
- 修复发布版网页启动器双击后无反应的问题，将批处理文件统一为纯 ASCII 和 Windows CRLF 换行格式。

### 发现的问题

- 列表渲染与导出筛选原先各自维护季度归类逻辑，容易出现同一部番在不同功能中被分到不同季度的问题。
- 追番原先始终按照首播日期归类，无法表现跨季度播出的进度。
- 补番原先始终按照开始观看日期归类，不能随系统时间移动，也不能在完成后按照看完日期固定归档。
- 补番通过进度按钮完成时不会自动填写看完日期，导致按看完季度归档缺少可靠数据。
- 0 集进度会被自动识别为“想看”，但提醒逻辑只接受“在看”，因此新添加且尚未观看的连载番不会提醒。
- 部分番剧的首播日期与后续固定更新时间不是同一星期，原先保存时总是根据首播日期重新计算，无法记录真实更新时间。
- Electron Builder 会自动收集 `package.json` 中的生产依赖，导致旧便携包把 Android 依赖的 `build/.transforms`、`intermediates` 等缓存一并带入。
- 旧的根目录 `启动PC版.cmd` 实际启动 Vite 开发服务器，既依赖 Node.js，又不适合作为交付给普通用户的网页版启动器。
- 根目录 `1.png` 与 `www/1.png` 内容完全相同，属于重复文件；历史分析文档也与日常开发文档混放，降低了目录可读性。
- 网页启动器最初以无 BOM 的 UTF-8 和 LF 换行发布，`cmd.exe` 在部分 Windows 本地代码页下会错误拆分命令，导致窗口立即退出。
- 清理后的本机缺少 Android SDK 与 `android/local.properties`，首次同步 Android 发布版时无法找到 API 35 平台，需要临时恢复官方命令行 SDK 才能完成构建。

### 当前问题

- Android 当前仍可正常构建，但 Gradle 报告部分依赖使用了弃用特性；未来升级到 Gradle 9 前需要先升级或调整对应的 Capacitor/Gradle 依赖。
- Windows 安装包目前没有可用的代码签名证书，安装器可以正常使用，但首次运行可能出现 Windows SmartScreen 提示。
- `npm audit` 当前报告 9 个间接依赖漏洞（2 个中危、6 个高危、1 个严重）；修复建议涉及依赖升级，本次保持 v1.2.0 功能范围，未执行可能产生破坏性变更的 `npm audit fix --force`。

### 踩过的坑

- 不能直接用当前系统季度无限移动追番，否则已经停止播出但尚未看完的番剧会一直跟随年份和季度漂移；因此需要用预计末集播出日期作为上限。
- JavaScript 的 UTC 日期格式化在部分时区可能把本地日期偏移到前一天，因此季度归类和自动完成日期均使用本地年月日。
- “想看”提醒不能只放宽状态判断，还要校验首播日期和预计末集日期，否则会在开播前或播完后产生错误提醒。
- 手动更新时间不能只增加选择框；保存逻辑也必须优先读取选择值，否则仍会被首播日期推断结果覆盖。
- 备份格式测试原先写死了 v1.1.0；升级应用版本后必须同步测试期望值，否则功能正常但发布检查仍会失败。
- Android SDK 路径在 `local.properties` 中使用 Gradle 转义格式（例如盘符冒号写成 `\:`）；发布校验脚本读取后需要先还原转义，才能正确找到 `apksigner`。
- Windows 下如果旧版 PC 可执行文件正被进程映射，覆盖同步会短暂失败；需要待文件锁释放后单独重试 EXE，并重新校验 EXE 与 `app.asar`。
- 仅在压缩后删除缓存不可靠；必须同时从 Electron Builder 的文件规则排除移动端依赖，并在便携版整理脚本中执行二次清理。
- 统一展示名称时不能同时修改 Android applicationId、Electron appId 和既有本地存储键，否则会破坏应用升级关系或让已有数据不可见；这些内部兼容标识继续保留旧值。
- 项目已有大量未提交文件和发布产物，发布同步时需要保留现有源码改动，并只刷新明确指定的 PC、Android 产物。
- 缓存测试版不能只预置一份随机缓存；需要让 Electron 在启动早期切换 `userData` 路径，并用随包标记区分正式版和测试版，否则两者仍会读写系统用户目录中的同一份数据。
- 网页版不能直接双击 `index.html`，浏览器对 ES Module 和本地文件协议有限制；发布包必须通过本机 HTTP 服务启动。
- Windows PowerShell 5 会把不带 BOM 的 UTF-8 脚本按本地代码页解析；包含中文路径时甚至可能产生伪语法错误，因此发布用 `.ps1` 文件需要保存为带 BOM 的 UTF-8。
- Windows 批处理与 PowerShell 脚本的编码要求不同：`.ps1` 使用带 BOM 的 UTF-8，`.cmd` 则应避免本地化文本并使用纯 ASCII + CRLF，才能稳定支持双击启动。
- Android `aapt` 在当前 Windows 本地代码页下不能可靠读取含中文目录的 APK 路径；产物本身不受影响，校验应用名称和版本时需要先复制到纯 ASCII 临时路径，完成后立即删除临时副本。
